# FaceScore · 男士颜值评分器

> **在线直接使用（无需下载，支持手机浏览器）：<https://xinghaowen986-afk.github.io/face-score/>**
>
> 想离线或本地跑，就下载本仓库后双击 `start.cmd`，见下文。

一个跑在浏览器里的本地面部比例评分程序：上传一张正脸照，程序用 MediaPipe Face Landmarker 定位 478 个面部关键点，测量 25 项几何比例，输出 6 个维度的得分、一个 0–99 的综合分，以及具体的改善建议和可导出的结果图。

**照片全程只在本机浏览器里处理，不上传；模型已内置，断网也能算分。**

主要功能：

- **裁剪 / 缩放**：上传后先进裁剪界面，可以拖动、缩放、套 1:1 或 3:4 构图，只把框住的画面送去评分。
- **多人同框对比**：一张照片里最多 8 个人，分别打分并自动排名，直接看出谁分更高，点谁看谁的详细报告。
- **测下一张**：每次测完都有明显的「测下一张」按钮，连着测多张不用重新找入口。
- **历史记录**：每次测量都会存进本机历史，点任意一条就能完整还原当时的报告（含关键点、六维分数、全部测量数据）。
- **人物档案**：同一个人换不同照片来测，程序会用面部几何指纹自动归到同一个档案，累积平均分、最高分和变化趋势；归错了可以「不是同一个人」拆开，也能随时改名。

## 一、怎么用

1. 双击目录里的 **`start.cmd`**。
2. 浏览器会自动打开 `http://127.0.0.1:8731/`（端口被占用时自动往后找可用端口）。
3. 用任意一种方式给程序一张照片：
   - 点「选择照片」；
   - 把图片文件拖到虚线框里；
   - 截图后直接 Ctrl+V 粘贴；
   - 点「打开相机」现场拍一张（正对镜头、平视）。
4. 在裁剪界面拖框、缩放，框住想评分的区域，点「开始评分」。
5. 结果自动出现：总分、分档、可信度、六维雷达图、逐项数据、改善建议；多人同框时会先给出排名和对比卡片。
6. 点「测下一张」继续测；点右上角「历史记录」「人物档案」可以回看任何一次结果，或看某个人的分数变化。点「导出结果图」可以保存单人报告卡或多人对比卡。

**为什么要用 start.cmd，而不是直接双击 index.html？**

浏览器的相机接口只在 `http://localhost` 或 https 下可用，本地模型文件通过 `file://` 打开时也会被跨域策略拦住。直接双击 index.html 只能用 CDN 兜底模式（需要联网），并且无法使用相机。`start.cmd` 会启动一个零依赖的本地静态服务器（`serve.ps1`，用系统自带 PowerShell 写成，不需要安装任何环境，也不需要管理员权限）。

## 二、评分是怎么算出来的

六维权重按男性面部特征的审美倾向设定；程序不识别性别，也不限制照片里的人是男是女。

| 维度 | 权重 | 测量内容 |
| --- | --- | --- |
| 骨相轮廓 | 22% | 面部宽高比 fWHR、脸型宽长比、下颌宽度比、下颌角、额头宽度比 |
| 五官比例 | 20% | 上庭 / 中庭 / 下庭占比、五眼比例、内眼距比 |
| 眉眼 | 18% | 眼型倾斜（外眼角高低）、眼睛开合度、眉眼间距、眼裂长度比 |
| 鼻部 | 12% | 鼻宽比、鼻宽 / 嘴宽、鼻部立体度（关键点深度）、鼻长占比 |
| 唇形下颌 | 13% | 唇厚比、下唇 / 上唇、嘴宽比、人中占比、下巴占比 |
| 对称协调 | 15% | 左右关键点镜像对称度、双眼水平度 |

每一项都按「离参考区间越远扣分越多」的高斯衰减函数打分，维度内加权平均，再把六维均值映射成 0–99 的总分：

`>=92 顶级建模脸 · 86-91 男神级 · 79-85 帅哥级 · 72-78 中上水准 · 64-71 邻家耐看 · <64 潜力股`

### 参考区间的来源（重要）

参考区间不是拍脑袋定的：先把 8 张公开测试人像（MediaPipe 官方素材库中的多人像）跑一遍关键点检测，取每项比例在样本中的**中位数作为参考区间中心**，再用样本离散度设定容差带宽。

也就是说，这里的「高分」= 接近普通人像的平均比例模板（面部平均化本身就是被反复验证的吸引力因素之一），不是绝对美学标准，更不是医学结论。样本量只有个位数，属于工程标定，不构成统计结论。

想改判定标准，改 `index.html` 中 `computeMetrics()` 里每个 `add(...)` 的 `ideal`（理想值）、`sigma`（容差）和 `weight`（权重）；想改维度权重，改顶部的 `DIMS` 数组。

## 三、人物归类是怎么做的

没有用人脸识别模型，而是用一个**面部几何指纹**：把 45 个稳定的关键点（面部轮廓、眉眼、鼻部、嘴部）换算到「以双眼连线为基准」的坐标系里（对齐、缩放、旋转都消掉），展平成 90 维向量，再算两个指纹的均方根距离。比较时还会顺带比一次「镜像版本」，所以自拍镜像和普通照片也能对上。

阈值是拿真实图片量出来的（MediaPipe 官方素材库的人像，同一张脸的不同尺寸与不同旋转角度，以及完全不同的几个人）：

| 对比 | 指纹距离 |
| --- | --- |
| 同一个人：原图 vs 缩小版 | 0.010 |
| 同一个人：原图 vs 旋转 90° 版 | 0.021 |
| 同一个人：缩小版 vs 旋转版 | 0.022 |
| 不同的人之间（10 组） | 0.057 – 0.100 |

同一个人的距离在 0.023 以内，不同人最近也有 0.057，中间留了足够空隙，程序取 **0.038** 作为判定阈值 —— 距离小于它就算同一个人，否则自动新建档案。界面上显示的「相似度」= `100 − 距离 × 900`，同一个人通常落在 80–91，正好卡在阈值上约 66。

样本量小、方法也简单，所以一定会出现归错的情况（换发型、戴眼镜、侧脸、极端光线都会影响）。归错随时可以改：在报告里点「不是同一个人」就能把这张脸单独建档，或者在人物档案里改名。

## 四、什么情况下结果会不准

程序会主动检测并提示这些情况，必要时跳过不可比的指标：

| 情况 | 处理方式 |
| --- | --- |
| 张嘴 / 微笑 / 说话 | 微笑会明显拉宽嘴部和鼻翼，唇形相关 3 项自动跳过并提示 |
| 头左右转 > 22 度 | 三庭五眼、对称度会失真，可信度下降并提示 |
| 俯仰 > 18 度 | 下庭长度、下颌线被压缩或拉长，可信度下降并提示 |
| 人脸占画面 < 24% | 关键点精度不足，提示靠近重拍 |
| 画面过暗 / 过曝 | 提示补光或降低曝光 |
| 画面里有多张脸 | 自动选面积最大的一张，并提示 |

注意「可信度」和「分数」是两件事：可信度低说明**这张照片的测量条件不好**，不代表分数一定偏低。同一张脸换光线、镜头、角度，分数浮动 5–10 分是常态，所以程序提供多次测量取平均。

## 五、文件结构

```
face-score/
├─ index.html          主程序（界面 + 评分算法 + 导出结果图）
├─ start.cmd           双击这个：启动本地服务并打开浏览器
├─ serve.ps1           本地静态服务器（PowerShell，零依赖、免管理员）
├─ README.md           本说明
├─ THIRD-PARTY-NOTICES.md   内置模型与运行时的许可声明
└─ vendor/             内置推理运行时，离线可用
   ├─ vision_bundle.mjs
   ├─ face_landmarker.task      人脸关键点模型（3.7 MB）
   └─ wasm/                     推理引擎（SIMD 与非 SIMD 两版）
```

删掉 `vendor/` 就会退回「从 CDN 下载模型」的模式（需要联网）；留着它就是一个完全离线的本地程序。

`vendor/` 里的文件是 MediaPipe 官方发布物的原样副本（Apache-2.0），来源与版本见 `THIRD-PARTY-NOTICES.md`。

## 六、隐私

- 图片只在浏览器内存里解码、绘制、测量，不发起任何上传请求；模型和推理引擎都是本地文件。
- **历史记录与人物档案保存在本机浏览器的 localStorage 里**（每条约 40–50 KB：一张缩略图、一张预览图、关键点、分数和测量数据），不会上传到任何服务器，也不会写入磁盘其他位置。默认保留最近 30 条，超出时自动丢弃最旧的；存储空间不足时也会从最旧的开始清理。
- 「清空全部历史」会同时删掉记录和人物档案，并清空 localStorage 里的对应数据。
- 相机流只在点「拍摄并分析」时取一帧，关闭相机立即释放摄像头。
- 换浏览器、换设备或用无痕窗口，历史不会跟过去。

## 七、免责声明

这是一个把面部几何比例量化成数字的**娱乐工具**。它不衡量气质、谈吐、身材和穿衣品味，也不是医学、心理学或人格评价，不应该被用来评价他人或否定自己。分数低只说明「这张照片的几何比例偏离平均模板」，不说明你不好看。请勿用于招聘、筛选、匹配等会影响他人权益的场景。
